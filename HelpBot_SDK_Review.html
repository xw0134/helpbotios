HelpBot SDK 深度审阅报告

本报告针对 HelpBot SDK（Android 版）的最新代码进行了深度审计，重点核查了登录防呆、日志分级、初始化参数、JS 交互逻辑、FAQ 显示及大屏兼容性五个核心维度。以下是详细审阅结论：

1. Login 接口防呆机制 已完成

需求描述：检查 login 是否已做防呆，是否必须先完成 install 才可以执行。

核查结果：已严格落地。`HelpBot.login` 内部通过 `verifyInstall()` 强制校验初始化状态。

// HelpBot.java L498-504 if (!HelpBotContext.verifyInstall()) { HBlogger.w(TAG, "login: SDK 未初始化，请先调用 HelpBot.install(...) 完成初始化后再登录"); notifyFailure(callback, HelpBotErrorCode.SDK_NOT_INITIALIZED, "SDK 未初始化：请先调用 HelpBot.install(...) 完成初始化后再登录"); return; }
  • 状态前置：任何非初始化状态下的登录调用都会被立即拦截，不再进行后续的 Token 缓存或 WebSDK 触发。
  • 错误透出：通过回调明确返回 `SDK_NOT_INITIALIZED` 错误码及中文引导文案。

2. WebSDK 日志分级与控制 已完成

需求描述：排错只需要 SDK 原生日志。正常情况下 WebSDK 不应有输出，仅在调试时开启。

核查结果：已在 WebView 控制台拦截器中实现双重开关控制。

// HelpBotWebViewHelper.java L416-422 if (!BuildConfig.DEBUG || !HelpBot.isDebugMode()) { return super.onConsoleMessage(message); } WebViewConsoleLogger.log(message.messageLevel(), TAG, ...);
  • 默认静默：生产环境（Release Build）下完全禁用了 Web 控制台日志的原生透传。
  • 按需开启：仅当 APK 处于 Debug 模式 且 用户在 `install` 配置中显式开启了 `debugMode` 或 `enableLogging` 时，Web 侧日志才会输出到 Logcat。

3. 初始化回调可选参数化 已完成

需求描述：`HelpBotInitCallback` 变更为可选参数。

核查结果：SDK 已提供多组重载方法，并将回调参数标记为 `@Nullable`。

// HelpBot.java L217 public static void install(@NonNull final Context application, @NonNull final HelpBotConfig config, @Nullable final HelpBotInitCallback callback)
  • API 灵活性：客户如果不关心初始化结果，可以调用不带回调的 `install(application, config)`。
  • 空安全性：内部调用逻辑如 `notifyInitSuccess` 均已做 null 检查，确保无此参数时逻辑依然稳健。

4. JS Bridge 监听逻辑 已完成

需求描述：核查 JS 通信与监听逻辑的完整性。

核查结果：`ChatToNativeBridge` 层提供了完整的事件映射，支持 SDK 准备、认证失败、SSE 消息等核心事件。

  • 事件分发：`sendEvent` 采用后台线程解析 JSON，有效防止 UI 卡顺。
  • 双向通信：通过 `window.HelpBotNativeAndroid` 暴露接口，对齐了 `websdk总结.md` 中的协议标准。
  • 安全性：对事件名进行了字符过滤（仅允许 A-Z/0-9/_），防止脚本注入攻击。

5. FAQ 显示功能 已完成

需求描述：核查 FAQ 模块的显示逻辑。

核查结果：已实现 `showFAQs`、`showFAQSection` 和 `showSingleFAQ` 三大入口。

  • 安全跳转：跳转至 FAQ 页面前会自动附加当前的 JWT Token，支持 `faqTokenQueryKey` 自定义。
  • URL 协议：强制要求 FAQ 链接必须为 HTTPS 协议，保障通信安全。
  • 容器化：通过专用的 `HelpBotFaqActivity` 进行渲染，与普通对话窗口互不干扰。

6. 大屏幕/平板兼容性适配 已完成

需求描述：核查大屏终端上的观感与布局。

核查结果：通过多级 `dimens.xml` (values-sw600dp/sw720dp) 和约束布局（ConstraintLayout）实现了响应式设计。

<!-- helpbot_activity_main.xml L38 --> app:layout_constraintWidth_max="@dimen/helpbot_max_width"
  • 最大宽度限制：在平板设备上，内容区最大宽度限制为 800dp 并自动居中，防止内容拉伸导致观感廉价。
  • 间距动态化：工具栏高度与页面边距随屏幕尺寸动态调整（例如大屏上边距从 0 变为 16dp），提升呼吸感。
