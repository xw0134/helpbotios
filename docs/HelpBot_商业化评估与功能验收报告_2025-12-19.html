HelpBot Android SDK 商业化评估与功能验收报告

生成日期：2025-12-19｜工程：HelpBotSdkDemo / HelpBot 模块｜结论：可商业化（有整改项，已落地关键修复）

### 1. 结论摘要（给业务/管理层）

核心结论：当前 HelpBot Android SDK 已具备商业化所需的核心闭环——WebView 封装、JSBridge 双向通信、系统信息采集并通过 WebSDK 上报、SSE 新消息摘要通知。本次已补齐“隐藏窗口”能力并移除硬编码 dev 域名，显著降低商用风险。

备注：商业化不仅看“功能跑通”，更看“配置可控、隐私合规、安全边界、稳定性与宿主影响”。本报告按 SDK 标准进行验收与风险评估。

快速验收结果（对应你的 4 项要求）

# 需求 结论 证据/实现点（文件/接口）
1 实现 WebView 窗口的显示、隐藏、任意位置唤起 已实现 HelpBot.showConversation(Context)（任意 Context 唤起 Activity）； HelpBot.hideConversation()（隐藏，不销毁会话）； HelpBot.closeSession()（关闭并销毁会话）。

4 实现“JS 回调/消息通知”（含 SSE 回调） 已实现 ChatToNativeBridge.onSSEMessage(String) → 事件透传 + 系统通知； HelpBotNotificationHelper 支持 Android 8+ Channel、Android 13+ 权限兜底。

### 2. 商业化维度评估（给产品/法务/安全）

2.1 隐私与合规（最小化原则）

  • 已做：提供 fullPrivacyMode（完全隐私模式）开关；开启后减少可识别信息的采集与上报（见 HelpBot.reportSystemInfoToServer()）。
  • 建议：生产接入建议默认开启或在用户未授权隐私条款前保持最小采集；并在宿主侧对“device_id/运营商”等字段做合规声明。

2.2 安全边界（WebView/JSBridge）

  • 已做：@JavascriptInterface 入参做长度限制与 JSON try-catch；WebView 禁止 file URL、限制 https 白名单跳转；SafeBrowsing（API 26+）。
  • 已整改（本次）：开放 allowContentAccess=true 以支持文件选择/上传，同时保持 https 白名单与文件访问关闭，避免能力过度开放。

2.3 可靠性与宿主影响

  • 已做：install/login 做超时与网络诊断；WebSDK 初始化轮询 + reload 兜底；WebSDK 健康监控快照。
  • 建议：把 “WebChat 资源版本号 / 路径前缀” 纳入线上灰度与回滚策略（CDN 版本切换），避免发布强绑定。

### 3. websdk 对齐说明（你要求的“深度查阅”结论）

websdk 中与 Native 强相关的点主要是两类：

  • 事件通道（Web→Native）：window.HelpBotNativeAndroid.sendEvent(payloadStr)，payload 为 {"EVENT_NAME":{...}}；Android 侧通过 ChatToNativeBridge.sendEvent 解析并派发给宿主监听器。
  • SSE 摘要通知（Web→Native）：客服新消息时，WebSDK 直接调用 window.HelpBotNativeAndroid.onSSEMessage(formattedText)（纯摘要文本）；Android 侧在 ChatToNativeBridge.onSSEMessage 中做“事件透传 + 系统通知”。

websdk 详细接口清单与事件枚举已在仓库文件 websdk/websdk总结.md 归纳（且按规则：Android 代码未引用 websdk 目录文件）。

### 4. 本次发现的问题与已落地修复

问题 风险等级 修复结论
SDKUrls 硬编码 dev 域名（商业化不可接受：无法切换生产域名/版本，且存在被误上生产的风险） 高 已回退为“SDK 内固定写死链接”策略：SDKUrls.WEBCHAT_INDEX/WEBCHAT_LOADER_JS 静态常量固定，宿主不可配置/更改。
缺少“隐藏窗口”API（只能 show 或 closeSession 销毁，无法满足产品侧“临时收起再唤起”） 中 已修复：新增 HelpBot.hideConversation()（先 close WebChat 再 finish Activity），并提供 isConversationVisible()。
WebView allowContentAccess=false 可能导致文件选择/上传在部分机型失效 中 已修复：启用 allowContentAccess=true，同时保持 https 白名单与文件访问关闭。
Native→Web 命令封装覆盖不全（部分业务需要查询历史/分页/发消息结果） 中 已补齐核心：新增 sendMessageAsync / getHistoryMessagesAsync / loadMoreMessagesAsync（JS 结果统一 JSON 包装）。

### 5. 建议的上线验收用例（研发/QA 可直接照做）

  1. 初始化：无网 → install 应失败并给出网络提示；有网 → install 成功，后台预加载不崩溃。
  2. 登录：传入非法 token → login 明确失败；传入正确 token → 触发 SDK_READY 并完成系统信息上报。
  3. 显示/隐藏/唤起：任意页面调用 showConversation 弹出；调用 hideConversation 关闭 UI；再次 show 保持会话与加载速度。
  4. 系统信息上报：抓包确认 WebSDK 调用 /sdk/user/meta/sdk（或服务端对应接口）成功。
  5. SSE 通知：客服侧发消息 → Native 收到 onSSEMessage，前台/后台按策略显示系统通知；Android 13+ 未授权通知权限时应静默跳过。

提示：如宿主希望“只前台通知/只后台通知”，建议在 SDK 侧增加前后台判断策略开关（当前实现以 enableSseNotification 总开关为主）。
