HelpBot Android SDK：install 阶段无感知初始化（不修改 websdk JS）方案

约束前提（必须满足）：
  • 不修改 websdk/ 目录下任何 JS 文件。
  • Android 代码禁止引用 websdk/ 目录文件（仅可走远端 WEBCHAT_INDEX / WEBCHAT_LOADER_JS）。
  • 对外 API 保持三步：install、login、showConversation。
  • install 阶段不能展示 HelpBotActivity（透明 Activity 在部分系统/ROM 下黑屏不可控）。

1. WebSDK 初始化时序（为什么要这样做）

从 helpbot-loader.js 的逻辑可知：

  • Android 侧通过注入 window.HelpBotConfig 决定 loader 行为。
  • loader 加载 helpbot-sdk.js 完成后，会执行：
if (window.HelpBotConfig && window.HelpBotConfig.autoInit !== false) {
  HelpBot('init'); connectToServer();
} else {
  HelpBot('init'); // 仅初始化，不连接
}

因此当我们设置 autoInit=false（符合三步 install→login→showConversation）时： 不会触发 SDK_READY 事件（SDK_READY 发生在 connect/autoInitialize 完成之后）。 所以 Android 侧要判定 install 是否“完成初始化”，应使用 HelpBot('getStatus') 轮询到： loaded=true && initialized=true。

2. Android 侧最佳实践方案（主流、可靠、用户无感知）

核心思路：install 阶段在主线程预创建一个离屏 WebView，加载远端 H5 容器页，并在 onPageStarted 顺序注入： window.HelpBotConfig → helpbot-loader.js。 初始化完成后缓存 WebView；showConversation 时由 Activity 接管并展示同一个 WebView。

2.1 关键点 1：为什么用 MutableContextWrapper

  • WebView 构造必须在主线程；且直接用 Activity Context 创建的 WebView 容易泄漏 Activity。
  • 主流方案（Chrome/FB 等常用的预热方式）是：new MutableContextWrapper(appContext) 创建 WebView；展示时再 setBaseContext(activity)。
  • Activity 销毁时把 BaseContext 还原为 appContext，避免引用链泄漏。
  • 本项目实现位于：HelpBotWebViewSession。

2.2 关键点 2：install 阶段不启动 Activity

  • 旧实现：install 直接 startActivity(HelpBotActivity)，违反“用户无感知”。
  • 新实现：install 仅触发 HelpBotWebViewSession.preload()（离屏 WebView 预热）。

2.3 关键点 3：三步 API 的行为定义

  • install：
    • 创建/预热 WebView，完成 loader + HelpBot('init')（通过 getStatus 判定）。
    • 不 connect；不展示 UI。
  • login：
    • 执行 HelpBot('setTokenAndConnect', token)。
    • 若 login 早于 WebSDK 初始化完成：先缓存 token，待初始化完成后自动补发（降低时序不确定性）。
  • showConversation：
    • 启动 HelpBotActivity（常规做法：用 Activity 承载可见 WebView）。
    • Activity 接管同一个预热 WebView 并展示；接管后再调用 HelpBot('open')。

3. 稳定性与安全性设计（符合 Google/主流要求）

3.1 WebView 安全配置

  • 关闭 allowFileAccess、关闭 file-url 相关跨域能力。
  • 保留 allowContentAccess=true：用于文件选择/上传走 content:// 读取；并通过域名白名单限制页面来源。
  • Mixed Content 关闭：MIXED_CONTENT_NEVER_ALLOW。
  • 只暴露必要的 @JavascriptInterface（当前为 HelpBotNativeAndroid）。

3.2 不确定因素与兜底策略

  • 网络/脚本加载抖动：install 阶段 getStatus 轮询 + 超时后 reload 重试一次。
  • 调用时序不确定：login/showConversation 都是“可排队”的；初始化完成/Activity 接管后自动执行。
  • Activity 生命周期：Activity 销毁时解绑 WebView 并还原 Context，避免内存泄漏。

4. 本次落地的代码点（便于你审阅）

  • HelpBot.install：移除 install 启动 Activity；改为 preload。
  • HelpBot.showConversation：负责启动 Activity，并请求 open（由会话在 attach 后执行）。
  • HelpBotActivity：改为仅接管展示预热 WebView。
  • HelpBotWebViewSession：新增会话管理（预加载、轮询 getStatus、attach/detach、login/open 兜底）。
  • HelpBotWebViewHelper：新增 context 版本 init（支持 headless 预热）。

5. 可选的“最佳改进建议”（允许改 JS 时）

如果未来允许改 WebSDK（最佳做法）：
  • 让 HelpBot('init') 返回 Promise，并在 init 成功/失败时 resolve/reject，Android 无需轮询。
  • 在 autoInit=false 的分支也发送一次 SDK_READY（表示“init 完成但未 connect”）。
  • 在 loader 内部对脚本加载失败做指数退避重试，并向 Native 抛出明确错误码。
